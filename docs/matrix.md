# Support and limitation matrix (3.0 Diamond)

Every row states what actually ships, verified against the code and
the test suite, not what would be nice to have. Statuses:

- supported: implemented, wired through the service worker or server,
  covered by tests.
- partial: implemented with documented, real limitations.
- not supported: absent by design, not faked.

| Feature | Status | Notes and limits |
| --- | --- | --- |
| Subresource integrity (#531) | partial | The rewriter drops integrity attributes (rewritten bytes can never match an upstream hash); the engine verifies fresh script/stylesheet subresources over raw upstream bytes (SHA-256/384/512) before any transform, blocks tampered bodies with a 500 no-store + x-zl-sri response, and records decisions in the x-zl-sri header. Registry is memory-only per client; cached script entries hold transformed copies so cache-hit scripts record but never block; unsupported algorithms fall back to the compatibility serve (Chromium parity). Browser-gated by suite/e2e/sri.mjs. |
| Import maps (#554) | partial | The wasm rewriter rewrites import map bodies (mapped values ride engine routes, bare and scope keys stay; a 256 KiB parse cap keeps hostile maps bounded), so page module scripts keep resolving specifiers through the served map. The engine records each served document's imports map (memory-only, page-space-keyed) and resolves MODULE WORKER bare specifiers through the owning page's map at the serve seam; unknown bare specifiers fail natively, never an invented route. Scopes are not honored for workers (the serve seam does not know the importing module URL); browser-gated by suite/e2e/importmap.mjs. |
| Streaming HTML rewriting | supported | Chunked through a TransformStream; no full-body buffering. Links, iframes, scripts rewritten to engine paths. |
| Streaming CSS rewriting | supported | url() references rewritten. `<style>` blocks are one-shot inside the HTML stream; standalone stylesheets stream chunk by chunk with only the incomplete url( tail retained (2.4), byte-identical to the one-shot pass. No init script is injected for CSS: it is not a document, the bootstrap never runs there. |
| JS rewriting | partial | Rust/WASM JsRewriter exists and runs, but token-level rewriter decisions are not surfaced to tracing (documented tracing limit). |
| Frame-buster neutralization | supported | js::antiframe pass (shipped in 2.3): framed-detection guards fold to their not-framed values, `top.location` navigation writes sink into `self.zl_antiframe`, reads map to the page's own location; method-call sinks are optional-chained so they are silent no-ops with no runtime definitions. Runs on every script body and inline event handler after the URL-literal pass. |
| Opaque URL passthrough | supported | blob:/data: hrefs are never rewritten; isOpaqueUrl guards the fetch path. |
| Nested-route unwrap at decode | supported | A decoded destination that is itself an engine route (any host binding, stale double-wrap from old dists) is peeled to the innermost destination (bounded 8 layers) before transport. |
| Rotatable route prefix (b64u only) | supported | zl:config rotates the prefix at runtime and the shape persists across SW restarts (issue #17); the wasm rewriter, worker prelude and module-worker specifier pass all encode in the live prefix (issue #20). The mirror scheme (/m/ carrying the destination verbatim in the address bar, history and every page-visible route string) was removed in #32: a persisted mirror config coerces to b64u on restore, zl:config rejects any other scheme value, and decodePath no longer recognizes /m/ shapes. Unit-gated (Rust decode round trip, TS codec/worker tests); the browser job (issue #35, suite/e2e) runs the routing round trips in real Chromium on pushes to main and nightly. |
| Range-aware page cache | supported | Stored 200 entries answer Range requests with a real 206 slice instead of replaying the full body (issues #13/#18); fragment-only hrefs keep their payload on decode (#12). Vary responses are storable: the normalized field list and the selecting request's header values ride the entry and only matching requests hit; Vary: * stays uncacheable (#557). The entry cap is a hard bound: a failed eviction refuses stores and disables caching until the worker restarts (#548). |
| Conditional revalidation | supported | Stored entries keep the origin\u2019s validators (ETag/Last-Modified survive the hostile-header strip); the stale refresh sends If-None-Match/If-Modified-Since, and a wire 304 keeps the stored body and bumps the stored-at time instead of re-transferring it. no-cache entries are stored with a zero TTL and revalidate before every use (RFC 9111): only a 304 serves the stored body, a 200 replaces it, and a failed revalidation bypasses to the live path instead of serving stale; transformed-JS entries are dropped rather than revalidated (composed-copy protection, #35). no-store stays never-stored. |
| Escaped same-origin fetch reroute | partial | Same-origin non-asset requests from a rewritten page are rerouted against the origin recovered from the request referrer (issue #1 finding 3). No decodable referrer = passthrough; request bodies of escaped fetches are rerouted, so genuinely engine-local paths a page invents cannot be recovered. |
| Cross-origin subresource routing | supported | Foreign-origin http(s) requests from proxied clients (page, or engine-served worker via its #33 context) are routed through the full pipeline: the URL is the destination, so SSRF policy, header surgery, cookie jar, rewriter and netLog all apply. CORS preflights are answered by the engine for exactly what the page asked. Host-app and unresolvable clients passthrough with #30 telemetry; page-created blob workers and opaque URLs passthrough. Parser-inserted URLs, CSS url() and srcset covered because the seam is the fetch event, not page hooks (issue #34). |
| Wisp v2.1 transport | supported | All proxied traffic rides the same wisp hop; TLS terminates client-side in the vendored libcurl transport. Issue #11 fixed at the vendored seam: libcurl.js 0.7.4 surfaces an empty-body response only on a first body chunk or a clean end, so a close-delimited response whose end is the peer connection close (curl error 56, mbedTLS ssl_read 0) discarded a fully received header set; the seam patches CurlSession.stream_response at load time to surface it (scoped to RECV_ERROR on close-delimited bodies; length-delimited truncation and status-0 no-response failures still reject). Gated by the transport-gate workflow (real craigslist 302 through a local wisp relay, every push to main) and unit tests. |
| Runtime WebSocket bridge | supported | Page WebSocket goes through the SW bridge to the transport; lifecycle + direction traced, payloads never recorded. Since deep-integration item 4 the upgrade handshake carries the per-origin virtual identity: the initiator's Origin, the jar's cookies for the target and the per-site UA (an active fingerprint profile still wins; ws:/wss: map to http:/https: for lookups). The initiator origin comes from the message when the sender supplies it, else is recovered from the controlling client's route (worker-relayed sockets included - the relay runs in the page context); headers are engine-built only, so a page cannot smuggle handshake headers. |
| ws:// WebSocket targets | supported | Passed through to the transport as plaintext (#525) over the same wisp tunnel cleartext http uses; the old force-upgrade to wss:// sent a TLS ClientHello no plaintext origin can answer. Plaintext passthrough is traced. |
| Virtual origins + per-origin cookie jars | partial | RFC 6265 parsing (Domain/Path/Secure/HttpOnly/SameSite), jar is the sole Cookie source for engine requests. SameSite enforced only through the opt-in zl:sameSite knob (approximate site context from the request referrer). Set-Cookie on redirect hops is captured: the SW follows the hop chain itself (the transport surfaces 3xx) and captures every hop; a hop it cannot follow (307/308 with a stream body, 10-hop cap) is surfaced with its Location mapped to an engine route (issue #1 finding 1). |
| document.cookie virtualization | partial | Per-origin, synced to the SW via a transferred port. The jar view is pushed to the requesting client's port whenever a proxied response admits (or deletes) a Set-Cookie (#35), so a fetch-received cookie is visible without a re-read. Eventual consistency limit stays: a cookie deleted directly by local JS is not detected (no local deletion signal). |
| localStorage/sessionStorage scoping | supported | Scoped per virtual origin (same FNV1a36 id as cookie jars). |
| IndexedDB virtualization | supported | Open/deleteDatabase names prefixed per virtual origin; IDBFactory.cmp compares prefixed names (consistent ordering in-scope, absent when the host lacks it). databases() is exposed only where the host factory provides it, prefix-filtered with the prefix stripped (engine-own and other-site names never appear; an honest gap only where the host lacks the API, #555, see docs/storage.md). The shim installs via defineProperty on the page global: the old plain assignment silently failed in the sloppy-mode classic bundle (accessor-only Window properties), leaving the raw unscoped factory in place - caught by the browser E2E suite (#35). |
| Cache API virtualization | supported | open/delete/has/keys/match scoped to the virtual origin; own-entries only. Installed via defineProperty like IndexedDB (the assignment-installed shim never actually replaced the global in the sloppy-mode bundle; #35). |
| Storage event isolation | supported | The raw "storage" event carries the engine-origin prefixed key of whichever site wrote it. The bootstrap installs one real listener and re-dispatches only this site's events to page handlers, prefix stripped, storageArea pointing at the page's scoped Storage (#37). Other virtual sites' writes and engine-own keys never reach a page listener; onstorage and addEventListener("storage") are both covered; a read-only context keeps native delivery (documented). |
| BroadcastChannel isolation | supported | Channels silently move onto a site-prefixed real name; the page-visible .name keeps the page's spelling, so two virtual sites never hear each other's channels (#37). |
| window.name scoping | supported | Scoped through the site-scoped sessionStorage: same-site reloads and navigations keep it, another virtual site starts from empty (#37). A fresh context seeds its real browsing-context name from its frame element, so named-frame lookups like recaptcha's `parent.frames["a-<id>"]` keep working (#132). |
| cookieStore | facade (#534) | A per-virtual-site facade rides the zl:docCookie channel over the authoritative jar: get/getAll/set/delete are promise-based, change events fire on jar pushes, HttpOnly records are never exposed and a page-supplied Domain is ignored (host-only admission). Never the native engine-origin CookieStore. Residual: the record omits the upstream Domain string (the page host is opaque), and workers do not get the facade. |
| postMessage cross-window origin | partial | Both virtual sites share the one real engine origin, which is what cross-window postMessage surfaces as the origin; the control plane never rides postMessage (zl: messages travel over MessageChannel ports). Same-origin messaging between virtual contexts works, but the origin string is the engine's, not the virtual site's - documented limit (#37). Delivered sender identity converges across nested engine frames (#533): a stashed child's ev.source is the identical proxy that iframe.contentWindow returns, via the __zlCP child-window slot keyed by the minting realm's origin, so the contentWindow getter, the virtual-origin relabel and the window.parent seam share one proxy per child and realm; a pre-bootstrap child keeps its raw identity, and cross-origin children stay raw. Accepted by suite/e2e/vorigin-msg.mjs. |
| Worker virtualization | supported | Dedicated/shared workers get a prelude: importScripts routed through the engine, worker WebSocket bridged over postMessage; shared workers relay over their newest connect port through the same page-side relay (2.3). The SharedWorker constructor scopes its native name by virtual-site token, classic/module type and credentials mode (#260/#453). The real-Chromium E2E now compares native direct behavior with proxied behavior for same-site reuse and cross-site separation, exercises same-site connections from separate tabs, classic/module and credentials separation, verifies worker IndexedDB/cookie scoping, and closes one client port while checking the other remains usable. A reconnect after all test ports close verifies storage persistence; browser-forced termination and an explicit service-worker/engine teardown are not asserted because Chromium controls the SharedWorker lifetime. All virtual sites remain same-origin to Chromium. Module workers get import/export-from and import() specifiers rewritten in the body at serve time (absolute and relative http(s) become engine routes; bare specifiers pass through - no resolver, same limit as pages; a text pass, so a specifier-shaped string literal is rewritten too; dot-relative web-asset string literals (.js/.mjs/.css/.wasm, #131 - Vite __vite__mapDeps dependency maps) route against the script's own URL, not the document's). Page scripts get the same serve-time specifier pass (destination "script" JS bodies, #35): external module scripts and dynamic import() in classic scripts resolve through the engine; inline module scripts remain a rewriter gap (#36). The page cache stores the composed copy for transformed JS (specifiers, worker prelude), never the raw one; a stale worker/script entry is dropped rather than refreshed in place, so the next visit re-fetches and re-transforms (#35). |
| Engine-route CORS surgery | supported | Target Access-Control-* response headers are never valid on an engine route: they are dropped and replaced with the engine's own CORS facts on every proxied response and on the page cache before storing. Uncredentialed responses get `*`, credentialed ones get the engine origin plus allow-credentials. Cross-origin consumers fail closed; an arbitrary request origin is never reflected, because the bodies are jar-authenticated (issue #2). |
| srcdoc iframe subresources | partial | The rewriter rewrites an iframe srcdoc body like any nested HTML, so src/href inside it are engine routes. Chromium, however, does not make about:srcdoc frames service-worker clients (crbug.com/41411856, revert CL e1d141d72688): their subresource requests bypass the SW entirely, reach the engine static server and 404. Engine-side nothing can serve them; the extension host has no such gap because declarative interception is not client-bound. The browser E2E asserts the rewrite and the documented uncontrolled-404 state. |
| srcset data: candidates | supported | Opaque candidates are never rewritten: a comma-carrying data: URL stays byte-exact in the attribute while http(s) candidates become engine routes (#36). Chromium accepts such a candidate (as the only entry it decodes with currentSrc = the full data URL); which candidate a multi-candidate list selects is the browser's choice, not a rewrite fact. The browser E2E asserts the intact attribute, the preserved data URL decoding standalone, and the routed candidate decoding on a fresh load. |
| Engine error page | supported | Failed navigations answer with the engine-owned minimal error page: one honest category line (dns/tls/timeout/blocked/stream; unknown failures are stream, a cause is never invented), a retry action, and a machine-readable zl-error meta payload. No target URL is printed (#32). Subresource failures keep the honest 502 text/plain body. The no-control case cannot be answered by the engine and stays a documented embedder snippet (docs/error-pages.md) (issue #3). Issue #31 extends the page from transport failures to every in-engine navigation strand: a malformed engine route (category "route"), a disabled site and a policy block (category "blocked") answer navigations with the error page instead of a bare text/plain 403/404; subresources keep the short text body. Browser-regressed with an unlisted unroutable target and a malformed route (suite/e2e). |
| Service-worker registration for proxied sites | partial | register() spawns a real guest realm in a page-created DedicatedWorker (isolated, terminable, harness-preluded): install/activate/fetch events, waitUntil under a 5 s budget, a bridged guest fetch() through the full engine pipeline (SSRF, cookies, policy), quota-bounded kernel-side caches, registration.update() with realm replacement and unregister() teardown; accepted by the real-Chromium suite suite/e2e/guest-sw.mjs (#538). #576 makes registration truthful end to end: a script/scope argument the JS rewriter minted into an engine token route is decoded back over the bounded page-admitted zl:decodeRoutes oracle, the page register() promise settles only on the kernel confirmation that the guest realm is running (a rejection carries the kernel stable reason plus a SERVICE_WORKER diagnostic), a same-identity re-register is a native-style success, an early registration before the virtual-origin marker queues behind a bounded wait and fails closed (never against the raw engine route), and webbrowsertools.com/test-service-worker reports "Service worker is activated". Honest limits: the guest fetch dispatch budget is 250 ms (cache-hit answers only), caches are session-scoped (a page-realm CacheStorage probe sees the engine real empty cache, so site test pages honestly report the guest caches as empty), clients.matchAll() is [], no controller/controllerchange, no push, no messaging into virtual pages (docs/virtual-service-worker-phase2.md). |
| Download registry | supported | Counting passthrough with filename detection (content-disposition/URL) and cancellation. Ring persists to site-scoped IndexedDB across SW restarts (2.2); active entries at restart are honestly marked interrupted. No resume. |
| Session export/import | supported | AES-256-GCM + PBKDF2-SHA256 (120k iterations, hand-rolled base64). No plaintext secrets ever at rest. Import supports replace (default) and merge with per-cookie conflict rules (2.2). |
| Fingerprinting resistance | partial | One consistent profile across navigator/screen/Date/Intl/canvas/WebGL, mirrored onto upstream headers, compiled into both document and worker init scripts (2.3): WorkerNavigator surfaces, timezone/Intl, WebGL UNMASKED_* and OffscreenCanvas perturbation with the same seed, so worker-computed canvas fingerprints match the document's. Limits: fixed-offset timezone, no DST simulation, Date toString zone text stays native, default profile is a shared fixed fingerprint, not per-session randomness. |
| Session recording + replay | supported | zlRecord artifacts; deterministic given identical rings; replay compares reachability, status class, unrewritten-URL absence, plus the recorded WebSocket lifecycle and cookie-jar-shape facts against the artifact contract (direction/kind/URL shape; names and scopes, never values). Bodies, headers, timings and WebSocket payloads are never recorded, so never compared. |
| Opt-in rewrite tracing | supported | 512-decision ring, zero allocation while off. Token-level wasm decisions untraced. |
| Network inspector | supported | 256-entry ring with delta polling. A fixed-vocabulary request initiator is shown in the detail pane: minted cross-origin Fetch and XHR, engine-routed sendBeacon, worker fetch, EventSource (request Accept), resource kind (Request.destination) and navigation (Request.mode). Request.destination does not prove parser provenance. Same-origin requests that bypass the page re-emitter, Request-object fetch inputs and requests without verifiable evidence remain UNKNOWN. The internal marker is stripped before upstream forwarding and omitted from inspector/extension header views. Initiator client attribution may be unavailable after a service-worker restart. |
| Diagnostics | supported | 512 events, 256 trace references, one trace ID per request, secrets redacted on entry. |
| SSRF/destination protection | supported | One policy: local names blocked pre-DNS, every resolved IP re-checked pre-connect (rebinding-safe); loopback/private/link-local/metadata/unspecified/broadcast and IPv6 ULA/link-local blocked. Test-only two-key escape hatch (ZL_TEST_ALLOW_PRIVATE_DESTS=1 + ZL_TEST_EGRESS=1, #213) must never be set in production. |
| WebExtension compatibility | partial | Real runtime for content scripts, storage, tabs, messaging, alarms, permissions, webNavigation, webRequest, management. Some APIs, true isolated worlds and true extension service workers remain partial (see README limitations). |
| Extension background pages (MV2 background.page) | partial | The page classic inline and external scripts are extracted and executed in the background sandbox in document order, and background.page takes precedence over background.scripts exactly as in Chrome; a page with no scripts is a valid inert background. No DOM is provided: a page script that touches document or window fails the boot with the error recorded, and the page itself is not browsable. Full DOM hosting is architecturally unavailable inside the service-worker context; the runtime and the compatibility matrix surface this as a capability limit, never as an install error (#505). |
| SPA routing | supported | Client-runtime; covered by app unit tests, honestly not probeable by the HTTP compat suite (marked client-runtime in the scoreboard). |

Bounded by design: 256 network-log entries, 512 tracing decisions, 512
diagnostic events, 512KB interception body cap (BODY_LIMIT in
intercept.ts).


## Hybrid location policy

**Partial:** SiteConfig legacy/hybrid/off controls share the owner-page policy
across inline/external scripts, with bounded AST work and reason diagnostics.
Default migration, whole-pipeline buffering and browser scoreboard rollout
remain open. See [hybrid policy](hybrid-location-rewrite.md).
